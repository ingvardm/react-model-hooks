# Repository Guidelines

## Project Structure & Module Organization
- Source: `src/` — core classes and helpers.
  - `ModelBase.ts`: Non-React base class with subscription system for state and events.
  - `ModelWithHooks.ts`: `Model` class extending `ModelBase` with React hooks (`useState`, `useDerived`, `useEvent`).
  - `create-model.tsx`: Factory function `createModel()` that generates Provider, useModel, useModelInstance, and Context.
  - `common-types.ts`: Shared TypeScript types for subscriptions and events.
  - `utils.ts`: Helpers (`shallowEqual`, `computeDeps` for auto-dependency tracking).
- Entry: `src/index.ts` re-exports the public API.
- Build output: `lib/` (generated by TypeScript; never edit).
- Tests: `tests/` directory with Jest + ts-jest tests.
- Docs: root `*.md` and `Docs/*.MD` contain API notes and guides.

## Build, Test, and Development Commands
- `pnpm run build` or `yarn build`: Compile to `lib/` via `tsc`.
- `pnpm run test` or `yarn test`: Run Jest tests.
- `npx tsc -w`: Rebuild on change for local development.
- `yarn prepare`: Runs on install/publish to ensure artifacts are fresh.

## Architecture & Usage

### Core Classes
- **`ModelBase<TState, TEvents>`**: Base class with subscription-based state management (no React dependency).
  - `TState`: Required type parameter for state shape.
  - `TEvents`: Optional type parameter for events (defaults to `EventsScheme`).
  - `state`: The current state object.
  - `setState(patch)`: Merge-style update that notifies subscribers.
  - `reduce(fn)`: Compute next state from a copy of current state.
  - `onStateChange(cb)`: Subscribe to any state change.
  - `onValueChange(key, cb)`: Subscribe to a specific key change.
  - `onValuesChange(keys, cb)`: Subscribe to multiple keys.
  - `onEvent(key, cb)`: Subscribe to a typed event.
  - `dispatch(key, data)`: Emit a typed event.

- **`Model<TState, TEvents>`**: Extends `ModelBase` with React hooks.
  - `TState`: Required type parameter for state shape.
  - `TEvents`: Optional type parameter for events.
  - `useState(key)`: Returns `[value, setValue]` tuple with `useSyncExternalStore`.
  - `useDerived(mapper, deps?)`: Derive values from state with automatic dependency tracking via Proxy.
  - `useEvent(key, cb?)`: Subscribe to events and return a memoized dispatch function.

### Creating a Model
```ts
import { Model, createModel } from 'react-better-model'

type Todo = { title: string; done: boolean; id: number }
type TodoState = { todos: Todo[]; showDone: boolean }
type TodoEvents = { 'clear-todos': undefined }

class TodoModel extends Model<TodoState, TodoEvents> {
  constructor() {
    super({ todos: [], showDone: true })
  }
  addTodo = (title: string) => {
    this.setState({ todos: [...this.state.todos, { title, done: false, id: Date.now() }] })
  }
}

export const { Provider: TodoProvider, useModel: useTodo } = createModel(TodoModel)
```

### Using in Components
```tsx
function TodoList() {
  const model = useTodo()
  const [show, setShow] = model.useState('showDone')
  const visible = model.useDerived(s => s.todos.filter(t => show ? true : !t.done))
  const clear = model.useEvent('clear-todos')
  // ...
}
```

### createModel Output
- `Provider`: React component that creates/holds the model instance.
  - Accepts optional `value` prop for external instance.
  - Accepts optional `state` prop to sync external state.
  - Accepts optional `onChange` prop to observe state changes.
- `useModel()`: Hook to access the model instance within Provider.
- `useModelInstance(state?)`: Hook to create a standalone model instance.
- `Ctx`: The raw React Context for advanced usage.

## Coding Style & Naming Conventions
- Indentation: tabs (as per source files). TypeScript-first; avoid `any` in public types.
- Components: PascalCase; hooks start with `use*`; React files `*.tsx`.
- Exports: prefer named exports; expose public API via `src/index.ts`.
- Event keys: typed string literals (e.g., `'clear-todos'`).

## Testing Guidelines
- Stack: Jest + `ts-jest` with jsdom environment. Tests in `tests/` directory.
- Cover model behavior (state transitions, reducers, events) and hook usage with `@testing-library/react`.

## Commit & Pull Request Guidelines
- Commits: small, imperative, and typed (Conventional Commits recommended).
- PRs: include summary, rationale, usage snippet, and note any API changes; update affected docs.
